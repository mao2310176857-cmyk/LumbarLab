# 真实压敏布接入与边界

本文件保留采集固件与已有行为说明。硬件开发接手请先读 [HANDOFF.md](../HANDOFF.md)，实现步骤见 [硬件接入与自动驱动指南](HARDWARE_INTEGRATION.md)。默认运行仍只读串口；通过显式工厂加载接手方驱动后，可走同一自动控制调用链。

本项目已读取用户会话中的两份 Arduino 源文件，并原样保存到 `firmware/original/`。建议使用修正版 `firmware/ViTac16x16Json/ViTac16x16Json.ino`，目录与主文件同名，可由 Arduino IDE 打开。原始文件用作追溯，不能与修正版一起放入同一 sketch 目录编译。

程序默认模拟。真实串口功能仅接收传感数据；没有任何电机、气泵或阀门命令，也不向串口发送 `b`、`j`、`r` 等指令。当前材料未提供真实执行器协议、限位接线、行程标定或紧急停止闭环，网页中的动作仅为控制建议，真实执行器未启用。

## 固件与接线

原文件声明硬件为 Nano / Uno（ATmega328P）、CD74HC4067 ×1、级联 SN74HC595N ×2、16×16 压敏布和 20 kΩ 下拉电阻。本项目保留原源代码的接线及扫描顺序；原文件中的“已验证”不代表本项目做过实物验证。

| 功能 | Arduino 引脚 |
| --- | --- |
| MUX SIG / ADC | A0 |
| 74HC595 SER | D2 |
| 74HC595 SRCLK 与 RCLK | D3，按原源代码说明连接 |
| MUX S0、S1、S2、S3 | D4、D5、D6、D7 |
| MUX E#，低有效 | D8 |

修正版仅修复可从源代码确定的问题：

- 空载 16 帧求和由 `uint8_t` 改为 `uint16_t`，最大 4080，不再在求平均前溢出。
- 有响应点数 `nz` 改为 `uint16_t`，可表示全部 256 点。
- 帧号 `seq` 改为 `uint32_t`。
- 全零响应的峰值坐标保留 `pr=-1, pc=-1`。
- ADC 辅助检查使用 `int` 保存 0..1023，避免截断及差值无符号下溢；相同读数不能单独证明线路故障。
- 空载基线的说明明确要求先离开布面，不能把当前坐姿当作空载重新归零。

三个全局帧数组共 768 字节；基线采样临时求和为 512 字节，合计 1280 字节，另外仍需要串口缓冲、其他全局变量与栈。在本次环境未找到 `arduino-cli`，因此未完成 AVR 编译、实际 SRAM 余量检查、烧录、接线验证、实测帧率或带宽验证；应在 Arduino IDE 选择实际板型后检查编译报告并台架验证。

## JSON 帧

默认波特率为 **2000000**。一行一个 JSON 对象；以 `#` 开头的提示行和空行被忽略。使用 `raw` 与 `diff` 数组，不能把增强版的网格文本当成 JSON 接入。

| 字段 | 约定 |
| --- | --- |
| `seq` | 0..4294967295 整数帧号 |
| `t` | 0..4294967295 整数设备毫秒计时 |
| `base` | 0 或 1；0 表示板端未完成校准，禁止用于控制 |
| `diff` | 必需，256 个 0..255 整数，行优先 `row*16+column` |
| `raw` | 可选，256 个 0..255 整数；电脑端归零必须保留 |
| `peak, pr, pc, nz, sum` | 固件附带的统计信息；主机验证类型与范围，不依赖它们计算分区 |

每行限制 8192 字节；超长行会丢弃到下一个换行后再恢复。格式错误产生无测量值的无效帧。每一真实新帧以电脑端 `time.monotonic()` 记录到达时间，设备的 `t` 不作为新鲜度时钟。`read()` 只交付一次最新新帧，禁止拿旧帧反复刷新时间。重复帧与倒序帧丢弃；uint32 正常回绕允许；检测到可能重启时立即使信号失效并清除电脑端基线，需重新连接。协议没有 boot id，极早的历史包与重启无法完全区分，采用停止信任的保守处理。

## 八分区必须实测

`config/zones.json` 的字符串键 `1`..`8` 对应八分区，值为矩阵索引列表。初始全部为空，因为现有代码只能确定 16×16 扫描索引，无法确定真实布面的朝向和八个感测区位置。

1. 连接后观察 16×16 矩阵，用已知小面积载荷逐点检查左/右、上/下与行列方向，记录真实索引。
2. 按产品的 1..8 分区编号填写各区索引。每个分区至少一个索引，范围 0..255；同一索引不能在任何分区中重复出现。
3. 可保留不属于八区的未分配像素，但八区必须全部非空。部分填写的文件可以保留，聚合结果仍为 `null`，自动模式仍禁用。
4. 保存配置后重新连接串口，使程序重新读取映射。按实际分区逐区施加载荷确认编号对应关系。

区值为该区像素均值，单位是 ADC 除以 4 后的相对量，范围 0..255；没有力值标定时不能称为牛顿、千克或绝对压力。`raw_zones` 始终为原始 raw 均值，`zones` 为当前基线扣除后的均值。均值可以减少因每区像素数不同造成的面积偏差，但不能替代实物标定。

## 安全连接顺序与两类校准

1. 安装可选串口依赖：`python -m pip install pyserial`。模拟运行不需要此依赖。
2. 让布面完全空载，打开正确 sketch，选择实际 Nano / Uno 板型与串口，编译并烧录；关闭 Arduino 串口监视器后由本应用独占端口。
3. 在网页选择真实串口及 2000000 波特率。打开串口可能触发 Nano 自动复位，原固件会上电自动捕获空载基线，所以连接期间仍需空载。
4. 等待原始矩阵稳定。确认布面无人后使用网页“空载归零”。这只在电脑端对最近 1 秒的 raw 取平均：至少 5 帧、时间跨度至少 0.5 秒、最新 raw 距现在不超过 0.5 秒，每像素窗口最大值与最小值之差不超过 20。条件不满足时拒绝归零并解释原因。
5. 归零后每个像素采用 `max(raw - host_baseline, 0)`。直到下一新帧才交付新基线的结果。若后续缺少 raw，信号失效，不回退到另一套基线。断开、重连或检测到板端重启会清除电脑端基线。
6. 完成八区映射及验证后，再让使用者坐下调到舒适支撑，并使用“记住当前支撑”采集参考。**空载归零和记住舒适支撑是不同操作。** 布上有人时不可执行空载归零或在串口监视器发送 `b`。

此版本尚无实物执行验证。连接真实传感器仅能证明读数与软件建议是否符合预期；实际驱动执行器前仍需补齐执行器协议、独立急停、硬限位、最大行程/速度/持续时间、力或压力上限，以及离座、丢帧和异常读数时的板端保护。

## 记录采样节奏

电脑控制循环目标约 20 Hz；串口读取线程保留最新帧，超过消费速率的帧可能被合并，保存的 `frame_seq` 可用于识别间隔。本版实验记录不是无损的全速阵列采集器。每份记录同时保留已消费帧的原始矩阵、相对矩阵与八区均值。

执行器入口见 `lumbar/actuators.py`，已由 `lumbar/service.py` 实际调用：

- `ActuatorCommand` 携带方向、速度意图、原始签发时刻及有限动作时长。当前速度仍是模拟行程百分比/秒，不能直接传给 PWM；真实适配器必须定义并验证物理单位映射。
- `ActuatorDispatcher` 去重同一次动作，保留原截止时间；过期动作转为停止。停止、暂停、采集参考、归零、切换设备、内部故障和关闭服务均经过执行器接口。
- `SimulationActuator` 调用模拟设备；`DisabledActuator` 不发送任何硬件字节。默认串口仍使用后者，因而没有真实电机协议。
- `AppService(..., actuator_factory=...)` 为开发接入点。工厂接受 `(source, sensor_device)`，返回含 `enabled`、`is_hardware` 和 `execute(command)` 的适配器，可选 `close()` 释放资源。它不对网页暴露“强行启用”开关。
- `ActuatorResult(sent, acknowledged, message)` 区分派发和接收确认。已启用适配器执行失败或未确认接收会锁存故障并请求停止；恢复数据不会自动恢复动作。回执只表示适配器确认接收，不等于机械已经完成动作；真实位移/限位反馈仍需另行实现。
- 软件派发器无法在电脑断电、进程卡死时保证停机。真实适配器必须把剩余有效期正确转换为板端时间，并在板端独立执行动作超时、断连停机、限位及急停。电脑的单调时钟不可直接当作 Nano 的时钟。

## 型号未知时的推进方式

先完成算法到执行器的统一调用和替身测试；取得现有机构控制程序及接线后，实现唯一对应的驱动适配器。如果没有程序，可由执行器标签、出线、驱动板正反面及供电/接线照片识别，再确认停止方式和限位。

三份采集固件均占用 A0（ADC）、D2（74HC595 数据）、D3（移位/锁存时钟）、D4–D7（MUX 地址）、D8（MUX 低有效使能），串口为 2000000 波特率。其他引脚在这些文件中未用，不证明实物空闲。两份原程序和修正版均没有电机控制、限位或执行器反馈。

先在无人接触的台架验证停止、方向、短动作、限位与断连停机，再测量推进对压力信号的响应，确定实际动作强度和时长。只有这些关系验证后，才能将“接触偏轻 → 前顶”的软件规则用于该机构。最后启用压力闭环进行实物调参。当前未进行这一步，软件参数不构成实物参数。
