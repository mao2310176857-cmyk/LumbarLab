# Lumbar Lab · 智能腰靠 Demo

**给硬件接手同伴：**先读 [HANDOFF.md](HANDOFF.md)，详细实现见 [接入与自动驱动指南](docs/HARDWARE_INTEGRATION.md)。交接压缩包内还有可双击阅读的 `交接说明.html`。

围绕“先找到舒服的支撑，再让腰托维持这种接触”实现的电脑端实验 Demo。浏览器显示八区信号、手动微调、个人参考、自动跟随、异常暂停和实验记录；Python 本地服务负责设备、控制和保存。默认使用会随身体场景和腰托位置变化的模拟设备，不需要连接硬件。

自动控制已通过统一执行器接口派发方向、速度意图与动作时限，模拟设备也走这条路径。

**实物硬件已打通（2026-10-24）**：8 路压敏传感器 + Arduino Nano + 双继电器腰靠电机。
继电器为**低电平触发**，D8 = 继电器 A（后靠）、D9 = 继电器 B（前推），
方向已在实物上确认。串口模式下网页可实时驱动真电机。

## 硬件现状（2026-10-24 实测）

| 项 | 状态 |
|---|---|
| 传感器 | 8 路压敏，7 路正常；**#6（A5）无信号**，已在固件与配置中标记忽略 |
| 控制板 | **Arduino Nano**（CH340K，ATmega328P，5V 逻辑） |
| 继电器 | 双继电器模块，**低电平触发** |
| 方向 | D8 = 继电器 A = **后靠**；D9 = 继电器 B = **前推**（实物确认） |
| 串口 | 2000000 baud，实物通信稳定 |
| 网页 | 支持本机与局域网访问（`--host 0.0.0.0 --allow-lan`） |

> **Nano 与 Uno 的引脚差异（重要）**
> Nano 上 `A8 = PC0`、`A9 = PC1`，而 `D8 = PB0`、`D9 = PB1` —— **是四个不同的引脚**。
> 所以**不能**用 `analogRead(8)` 去读 D8 的电压（读的是 PC0，无关）。
> 继电器状态请用 `digitalRead`（读 PORT 寄存器）或万用表。

继电器控制的一个要点：`analogWrite(pin, 0)` **不是"关闭 PWM"**，
而是"开启 PWM、占空比 0%"，输出恒为低电平。要得到稳定的 HIGH/LOW，
只用 `digitalWrite`（Arduino 核心内部会 `turnOffPWM`）。

## 启动

需要 **Python 3.10 或更新版本**。模拟模式仅使用标准库，无需安装第三方依赖。

- **Windows：**在项目目录双击 `start_windows.bat`。
- **终端：**在项目目录运行 `python run.py`；macOS/Linux 可使用 `python3 run.py`。
- **不自动打开浏览器：**运行 `python run.py --no-browser --port 8765`，然后打开 <http://127.0.0.1:8765>。
- **局域网演示（队友在自己电脑上看）：**运行 `python run.py --no-browser --host 0.0.0.0 --allow-lan --actuator-factory integrations.hardware_adapter:create_actuator`，
  启动后会打印 `LAN access: http://<本机IP>:8765`，同一局域网内的其他电脑直接访问该地址即可。
  （不加 `--allow-lan` 时只接受本机 Host 头，这是防止局域网内网页被恶意控制电机的保护。）

新电脑建议按 [接手说明](HANDOFF.md) 创建项目 `.venv`，把依赖安装在同一解释器中。Windows 启动脚本依次检查项目 `.venv`、Python Launcher、PATH，最后才尝试原开发机器可用的 Codex 运行时；均需满足 Python 3.10+。脚本不会自动安装 Python 或依赖。终端也可运行 `.\start_windows.bat --no-browser --port 8765`。

服务运行期间保留终端窗口。停止服务时在终端按 `Ctrl+C`。如果端口被占用，可改为 `--port 8766`，并打开对应地址。界面和数据均由本机服务提供。

## 第一次演示

1. 保持“自然坐姿”场景，观察 1—8 区有连续读数。5、6、7 是同一块活动腰托的三个反馈点。
2. 如需调整，用“推出一点”“收回一点”小步微调；“停止”随时结束动作。
3. 点击“记住当前支撑”，保持场景与读数稳定约 3 秒。成功后出现个人参考范围。
4. 点击“开始记录”，打开“自动跟随支撑”开关。切换“身体前倾”，观察接触持续减弱后前顶；回到“自然坐姿”或切换“身体后靠”，观察回退及稳定后的保持。
5. 试试“支撑偏强”“刚刚好”“支撑偏弱”反馈；点击“停止并保存”，在实验记录列表点击“回放”或下载 JSON。
6. 切换“离开座椅”“腰部脱离”“信号掉线”或“异常数据”，确认自动暂停。恢复正常场景后，需再次明确打开自动开关。

进入回放会先暂停实时自动调节；之后播放、拖动历史进度不驱动设备。点击“返回实时”后仍需明确开启自动。详细操作和预期结果见 [验收流程](docs/acceptance.md)。

## 控制逻辑

- **个人参考：**从一段稳定读数计算八区均值和自然波动；空载、接触不足、失效或明显波动时不能建立参考。
- **算法名称：**个人参考驱动的带滞回区间反馈控制，配合状态机；当前没有 PID、自学习模型或自动寻找舒适点。
- **区间反馈：**5、6、7 的平均接触低于下界并持续一段时间后前顶，高于上界时回退；三个点还单独检查局部偏强，避免均值掩盖局部压力。
- **减少反复：**启动与停止采用不同阈值，并使用滤波、持续时间、小段动作和停稳间隔。
- **优先暂停：**离座、腰部接触丢失、数据失效或超时会停止并暂停自动；信号恢复不会自行重启。
- **手动接管：**手动命令退出自动，每次是有限小步。模拟位置限制在 0—100%，不是实物毫米值。

1—4 区用于判断是否仍在座，8 区用于显示与记录；这版不输出未经验证的具体坐姿名称。所有接触数值都是模拟或传感器的**相对信号**，没有标定为牛顿或实际压力。当前阈值用于软件演练，实际机构参数需要实测。

## 接入真实传感器

按 [硬件接入说明](docs/hardware.md) 核对协议、归零与矩阵映射后再连接。串口依赖按需安装：

```powershell
python -m pip install pyserial
```

请安装到启动服务使用的同一个 Python 环境。使用项目虚拟环境时运行 `.\.venv\Scripts\python.exe -m pip install -r requirements-serial.txt`。

界面选择串口并连接；现有 JSON 固件的默认波特率为 `2000000`。数据按 16×16 阵列读取，保留 `raw` 和 `diff`。`config/zones.json` 初始故意留空：通过逐处按压确认真实位置后，明确填写 1—8 区的矩阵索引；未完成映射时不能建立八区控制参考。

“空载归零”与“记住支撑”是两个不同操作。串口模式下，前者需要确认无人接触并利用 `raw` 在电脑端扣除基线，后者在人坐着且支撑舒服时采集。电脑端归零不会向板子发送 `b` 或其他命令。

接手方复制 `integrations/hardware_adapter_template.py` 为 `integrations/hardware_adapter.py` 并实现后，运行 `python run.py --actuator-factory integrations.hardware_adapter:create_actuator`。模板的真实串口分支会明确拒绝运行；它不是现成电机驱动。

真实电机接入使用 `AppService(actuator_factory=...)`：工厂按数据源创建适配器，适配器实现 `execute(ActuatorCommand) -> ActuatorResult`。自动调节、手动联调和停止都通过同一派发器，命令不会因反复刷新而续期；执行异常或未确认接收会暂停，检查并重新连接后才可重新开启。具体协议、供电、引脚、真实速度映射、板端超时及限位尚待确认和实现，不能直接把模拟速度当作 PWM 或毫米/秒。

不知道型号时，先取得现有能让机构运动的程序及接线；若没有程序，可根据执行器标签、驱动板正反面与接线照片识别。无需先由使用者判断电机类型。已知 A0、D2–D8 用于压力采集，不能直接复用作电机控制。详细接入条件见 [硬件说明](docs/hardware.md)。

## 实验记录

结束记录后，JSON 会保存到 `data/sessions/`。内容包含时间、原始/处理后读数、个人参考、控制参数、模式与控制决策、执行器派发/回执/故障状态、模拟位置，以及操作与体验反馈事件。JSON 可通过界面下载，之后重启服务仍能浏览已保存记录。

这些记录用于比较参数、核对动作与感觉反馈，不能将模拟数据当作真实人体或机构实验结果。记录中的真实执行器位置为空时，表示硬件尚未提供该反馈。

## 代码与验证

```text
run.py                 本地服务启动入口
lumbar/controller.py   个人参考、反馈控制与异常处理
lumbar/simulation.py   身体场景与模拟执行器
lumbar/devices.py      串口解析、矩阵映射与电脑端归零
lumbar/actuators.py    命令派发、去重与输出状态（默认无真实驱动）
lumbar/service.py      操作编排、状态与实验记录
lumbar/server.py       HTTP 接口及静态页面
web/                   无构建依赖的网页界面
config/zones.json      待实测填写的矩阵到八区映射
firmware/              固件修正参考
integrations/          硬件驱动接入模板
HANDOFF.md             给硬件同伴的接手入口
tests/                 自动化行为测试
```

运行软件测试：

```powershell
python -m unittest discover -s tests -v
```

使用项目 `.venv` 时，将上述命令的 `python` 换成 `.\.venv\Scripts\python.exe`。

测试覆盖控制状态、模拟反馈、异常暂停、参数与记录，以及串口协议解析；软件验证不代替真实传感器与机构的现场联调。
